## 2. 线上技术缺陷（F1–F11，线上现状）

> 每条五要素：现象 / 证据 / 影响面 / 严重度 / 判定依据。证据均可按 URL 与原始响应片段复现。

### F1 FAQPage JSON-LD 跨语种缺失

- **现象**：同一 slug 文章，FAQPage 仅 en/zh/hi 三个语种输出；es/fr/pt/de/ru/ja/ar 七个语种样本无 FAQPage 块。
- **证据**：10 语种同 slug `tanzania-ibr-roofing-fasteners-dar-es-salaam` JSON-LD 类型清单——有 FAQPage：en、zh、hi；无：es、fr、pt、de、ru、ja、ar。补充样本复核：en-b1/en-b2、zh-b1/zh-b2、hi-b1/hi-b2 有；其余语种 b1/b2 均无。源码侧：`src/app/[locale]/industry/[slug]/page.tsx` 的 `faqSchema` 由 `faqItems` 经 `nativeText(item.q/a, locale)` 过滤后生成，该语种无原生问答时整段 FAQPage 不输出。
- **影响面**：7 个语种的文章模板（按同 slug 跨语种一致推断；未全站逐条核对）。
- **严重度**：P2。跨语种内容/结构化数据不一致；缺失语种失去对应机器可理解标记。本条仅记录现状，不建议删除已有 FAQ。
- **判定依据**：GSC 帮助中心「FAQ 结构化数据」（FAQPage 须与页面可见 FAQ 内容对应；跨语种应保持对等）；规则卡 R26（移动/桌面两侧元数据等价，跨语种对等精神一致）。**口径提醒**：自 2026-05-07 起 Google 搜索不再显示 FAQ 富媒体结果（`appearance-structured-data.md` 冲突区；GSC 技能 FAQ 标记预期管理），保留 FAQPage 仅用于机器理解内容，**不为出 FAQ 富摘要返工**。

### F3 站内链接生成双斜杠

- **现象**：文章内链指向产品页时路径尾部出现双斜杠 `/{loc}/products/roofing-screws//`。
- **证据**：
  - `https://www.tradego-fasteners.com/en/industry/tanzania-ibr-roofing-fasteners-dar-es-salaam/` 内链：`/en/products/roofing-screws//`（锚文本 "Request a quote"）；
  - 同 slug zh、es 样本分别为 `/zh/products/roofing-screws//`、`/es/products/roofing-screws//`；
  - 该 URL 实测 308 → `/en/products/roofing-screws/`（1 跳），服务端可归一化，但生成层应输出规范单斜杠。
  - 源码侧：`industry/[slug]/page.tsx` 的 `ctaHref` 由 `/${locale}${(article.cta?.link || '/contact').replace(/^\/en(?=\/|$)/, '')}/` 拼接；link 字段若尾部已带 `/`，拼出即双斜杠。
- **影响面**：疑产品页 CTA 链接模板；抽样 3 语种复现。
- **严重度**：P2。多一次 308 跳转，浪费抓取预算并产生非规范 URL 变体。
- **判定依据**：R18（canonical/信号一致）、R22（避免多余跳转链）、R32（入口 URL 应一步到位）。

### H1 robots.txt 封堵 `/_next/`（含 `/_next/static` CSS/JS chunk）

- **现象**：robots.txt 每个 UA 分组均含 `Disallow: /_next/`；页面实际引用的渲染资源位于该路径下。
- **证据**：`https://www.tradego-fasteners.com/robots.txt` HTTP 200，原文片段：
  ```
  User-Agent: *
  Allow: /
  Disallow: /api/
  Disallow: /_next/
  Disallow: /admin/
  ```
  其余 19 个 UA 分组（GPTBot、ClaudeBot、PerplexityBot 等）写法相同。文章页 HTML 引用 `/_next/static/chunks/0~~nfj-_e4eqg.js?dpl=...`、`/_next/static/chunks/0t7f12ohppbeh.css?dpl=...`；该 CSS chunk 直接请求返回 `200 text/css`，资源存在且可访问，但被 robots 规则挡在抓取层。
- **影响面**：全站 4101 URL 的渲染资源；按 robots 前缀匹配，`/_next/` 同时覆盖 `/_next/static` 与 `/_next/image`。
- **严重度**：P1（潜在）。渲染关键资源被挡时，抓取渲染器拿不到样式/脚本，页面可能渲染不完整。
- **判定依据**：R8（不要随意封堵 CSS/JS 等渲染资源；被 robots 挡住的文件，Google 不会渲染其中的 JavaScript）；R7（路径前缀匹配规则）；GSC 技能「AI 爬虫 UA 规则会不会误伤 Googlebot」（渲染必需的 CSS/JS 不能被 robots 挡，否则「已抓取-尚未编入索引」会激增）。
- **状态**：**已修待发**。本地 `robots.ts` 与 `next-sitemap.config.js` 均已去掉 `/_next/` Disallow，仅保留 `/api/`、`/admin/`；明日构建上线后生效。
- **若明日构建未成功的退化后果**：线上维持现状，`/_next/static` 下 CSS/JS 继续被 Disallow；移动优先索引下可能出现渲染后 DOM 不完整、内容/链接理解偏差，甚至被误判 soft 404；需在 GSC URL 检查工具核对已加载资源列表与渲染后 DOM。
- **上线后复核**：robots 抓取模拟与 URL 检查工具复核 `/_next/static/` 资源可抓、渲染完整。

### H2 robots.txt 残留废弃 `Host:` 指令

- **现象**：robots.txt 末尾一行 `Host: https://www.tradego-fasteners.com`。

### H6 `dateModified` 与 sitemap `lastmod` 非真实修改日期

- **现象**：
  - 文章 JSON-LD `dateModified` 抽样全部为 `2026-11-25`，而 `datePublished` 跨样本为 2026-11-23 / 11-24 / 11-25；即发布更早的文章 dateModified 仍被刷成统一当日。

- **证据**：
  - 文章页：`"datePublished": "2026-11-23"`, `"dateModified": "2026-11-25"`（`/en/industry/asphalt-flash-band-buying-guide/` 等 b2 样本）。

  - 未发现未来日期 lastmod。
- **影响面**：全站 sitemap + 文章 dateModified。
- **严重度**：P2。lastmod/dateModified 不能反映真实重大更新时，Google 会忽略该新鲜度信号，并可能误导新鲜度判断。
- **判定依据**：R16（lastmod 仅在持续且可核实、与页面实际修改对比准确时才采用；应反映最后一次重大更新）；中央手册 §5 第 5 条（不得把所有 URL 的 lastmod 刷成构建时间）。
- **状态**：**已修待发**（本地已改真实日期；文章侧走 `resolveArticleDates` + freshness 缓存）。
- **若明日构建未成功的退化后果**：旧文继续挂构建当日 dateModified/lastmod，新鲜度信号不被采信；批量同一时间戳的 1702 条非文章 URL 尤其明显。
- **上线后复核**：抽查不同发布日期文章的 dateModified/lastmod 是否与实际更新一致。
